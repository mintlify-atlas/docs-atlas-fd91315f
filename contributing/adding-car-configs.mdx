Car configs in the CSP Extension Config repository tell Custom Shaders Patch how to illuminate a car — where its headlights, brake lights, turn signals, and emissive materials sit, how bright they glow, and how they cast light onto the surrounding track surface. Every `.ini` file in `config/cars/` is a community contribution that permanently improves the experience for every driver who loads that car. If you own a car that doesn't have a config yet, or if you've spotted one that needs improvement, this guide walks you through the full process from fork to merged pull request.

<Note>
The CSP Extension Config repository exposes two live status badges for cars in its README: **Cars configs status** and **Cars textures status**. These badges are powered by an automated checker at `cspdata.acstuff.club` and turn red when a committed config contains invalid mesh names, broken material references, or missing required keys. Always check that both badges remain green after your PR lands.
</Note>

## Contribution Workflow

<Steps>

### Fork the repository on GitHub

Navigate to [github.com/ac-custom-shaders-patch/acc-extension-config](https://github.com/ac-custom-shaders-patch/acc-extension-config) and click **Fork**. Clone your fork locally so you can edit files and push changes. The repository is structured with car configs living under:

```
extension/
└── config/
    └── cars/
        ├── common/       ← shared include files
        ├── kunos/        ← official Kunos cars
        └── mods/
            ├── acclub/   ← AC Club mod pack
            ├── acfl/     ← ACFL mod pack
            ├── fo/       ← Formula Origins pack
            └── rss/      ← RSS mod pack
```

### Find your car's folder name

Open your Assetto Corsa installation and look inside `assettocorsa/content/cars/`. Each subfolder name there is the car identifier. For example, the RUF Yellowbird is `ruf_yellowbird` and the BMW M3 E30 is `bmw_m3_e30`. The config file you create must be named exactly `<carfoldername>.ini`.

### Generate a guessed config to use as a starting point

CSP can auto-generate a first-pass config by reading the car's existing `data/lights.ini` and guessing light positions:

1. Create a directory called `extension_cars_guessed` inside your AC documents folder:
   ```
   %userprofile%\Documents\Assetto Corsa\cfg\extension_cars_guessed\
   ```
2. Launch Assetto Corsa and load the car you want to configure in any session.
3. CSP will write a guessed `.ini` file named after the car folder (e.g. `ruf_yellowbird.ini`) into that directory.
4. Exit the session and open the generated file — it contains rough `[LIGHT_HEADLIGHT_X]`, `[LIGHT_BRAKE_X]`, and `[EMISSIVE_LIGHT_X]` entries that you can refine.

<Tip>
The guessed config is a scaffold, not a finished product. Positions and colors will need manual tuning, but it saves you from writing all section headers from scratch.
</Tip>

### Copy the config to your fork

Place the file in the correct subfolder of your fork's `config/cars/` tree:

- **Official Kunos cars** → `config/cars/kunos/ruf_yellowbird.ini`
- **Mod cars** → `config/cars/mods/<packname>/carname.ini`

The `<packname>` segment groups configs by the mod pack or creator. For example, an RSS Formula car would go in `config/cars/mods/rss/`, while a standalone community mod with no parent pack can sit directly in `config/cars/mods/` at the top level. Use lowercase and underscores — no spaces.

### Edit the config live while Assetto Corsa is running

CSP supports **live reloading** of car configs. Copy your working `.ini` to:

```
%userprofile%\Documents\Assetto Corsa\cfg\extension\config\cars\
```

Then load the car in a practice session. Every time you save the `.ini`, the patch picks up the change within the same session — no restarts needed. This is by far the fastest way to tune positions and colors to match the real geometry.

### Add lights using the correct section types

Car configs support several numbered section families. Replace `X` with 0, 1, 2, … for multiple instances of the same type:

| Section | Purpose |
|---|---|
| `[LIGHT_HEADLIGHT_X]` | Forward-facing headlight cone with optional popup animation |
| `[LIGHT_BRAKE_X]` | Rear brake light cone cast onto the track surface |
| `[LIGHT_REVERSE_X]` | White reverse light |
| `[LIGHT_TURNSIGNAL_LEFT_X]` / `[LIGHT_TURNSIGNAL_RIGHT_X]` | Indicator light cones |
| `[EMISSIVE_LIGHT_X]` | Controls the glow of an emissive mesh (e.g. a brake-light lens material) |
| `[EMISSIVE_BRAKE_X]` | Emissive material that activates on braking |
| `[EMISSIVE_REVERSE_X]` | Emissive mesh for reverse lights |
| `[EMISSIVE_TURNSIGNAL_LEFT_X]` / `[EMISSIVE_TURNSIGNAL_RIGHT_X]` | Indicator mesh emissive |
| `[BOUNCED_HEADLIGHTS]` / `[BOUNCED_BRAKE_LIGHTS]` | Ambient bounce contribution from headlights / brakelights |
| `[LIGHTING]` | Global emissive multipliers for headlights, brake lights, and parking lights |

A `COLOR` value follows the pattern `r, g, b, brightness` where `r/g/b` are 0–1 floats (or occasionally > 1 for HDR) and `brightness` scales the overall intensity. `POSITION` is `x, y, z` relative to the car's centre node.

### Test thoroughly across all cameras and times of day

Before opening a pull request, verify the config under all common conditions:

- **Daytime** — headlights should not visually bleed; emissive materials should look correct in bright sunlight.
- **Nighttime** — headlight beams should project convincingly onto the track surface; brake lights should cast a red cone behind the car.
- **Cockpit camera** — `INTERIOR_ONLY` / `EXTERIOR_ONLY` flags on lights must be correct so dashboard elements don't clip through geometry.
- **Chase / chase far cameras** — the car should look lit from a distance; check `FADE_AT` and `FADE_SMOOTH` values.
- **Multiplayer** — load the session with another car instance if possible; light positions should not float off the body.

<Warning>
Incorrect mesh names in `EMISSIVE_*` sections are the most common cause of failed automated checks. Always verify mesh names against the car's KN5 file using a tool such as **KN5 Explorer** or **Content Manager's model viewer** before submitting.
</Warning>

### Open a pull request

Push your new config file to your fork and open a pull request against the `master` branch of the upstream repository. In the PR description include:

- The full car folder name (e.g. `ruf_yellowbird`)
- A brief summary of what sections you added or changed
- Whether you tested it in AC and with which CSP version
- Screenshots of the car at night if available — reviewers appreciate visual context

</Steps>

## Minimal Working Example

The following example is based on patterns from the well-commented `ruf_yellowbird.ini` reference config. It shows the most commonly needed sections for a front-engined, rear-wheel-drive car with popup headlights.

```ini
; Minimal car config — my_car.ini
; Based on patterns from config/cars/kunos/ruf_yellowbird.ini

[LIGHTING]
EMISSIVE_HEADLIGHTS_MULT   = 1.4
EMISSIVE_PARKINGLIGHTS_MULT = 2.5
EMISSIVE_BRAKELIGHTS_MULT  = 0.25

; --- Headlight (right side, mirrored to left automatically via MIRROR) ---
[LIGHT_HEADLIGHT_0]
POSITION            = 0, 0.64, 1.75   ; x=centre, y=height, z=forward
MIRROR              = 0.618            ; x-offset to mirror left side
DIRECTION           = 0, -0.2, 1
SPOT                = 52
SPOT_SHARPNESS      = 0
RANGE               = 300
COLOR               = 0.97, 0.98, 1, 10
OFF_COLOR           = 0.9,  0.9,  1, 13
OFF_MULT            = 0
FADE_AT             = 450
FADE_SMOOTH         = 50
EXTERIOR_ONLY       = 0
POPUP_ENABLED       = 1
POPUP_FILE          = lights.ksanim
POPUP_START         = 0.05
POPUP_END           = 0.7

; --- Brake light ---
[LIGHT_BRAKE_0]
POSITION            = 0,  0.55, -1.98
MIRROR              = 0.468
DIRECTION           = 0,  0,   -1
SPOT                = 165
SPOT_SHARPNESS      = 0.35
RANGE               = 3
RANGE_GRADIENT_OFFSET = 0.4
COLOR               = 1, 0, 0, 3
OFF_COLOR           = 1, 0.09, 0.03, 1.35
OFF_MULT            = 0.1
AFFECTS_TRACK       = 1
EXTERIOR_ONLY       = 1

; --- Emissive brake-light lens material ---
[EMISSIVE_BRAKE_0]
NAME                = brake_light      ; material name from the car's KN5
COLOR               = 20, 3, 0, 20
OFF_COLOR           = 10, 0, 0

; --- Emissive headlight lens ---
[EMISSIVE_LIGHT_0]
NAME                = headlight_glass  ; material name from the car's KN5
BIND_TO_HEADLIGHTS  = 1
LOCATION            = FRONT
COLOR               = 10, 10, 10
LAG                 = 0

; --- Reverse light ---
[LIGHT_REVERSE_0]
POSITION            = 0, 0.76, -1.84
DIRECTION           = 0, 0, -1
SPOT                = 175
SPOT_SHARPNESS      = 0.4
RANGE               = 5
COLOR               = 1, 1, 1, 5
OFF_MULT            = 0.1
AFFECTS_TRACK       = 1

; --- Bounced ambient from headlights ---
[BOUNCED_HEADLIGHTS]
ACTIVE              = 1
MULT                = 1
OFFSET              = 7
FALLOFF             = 0.7

; --- Bounced ambient from brake lights ---
[BOUNCED_BRAKE_LIGHTS]
ACTIVE              = 1
MULT                = 1
OFFSET              = 7
FALLOFF             = 0.7
```

## Naming Convention for Mod Car Configs

Mod car configs live under `config/cars/mods/` and follow a two-level naming scheme:

```
config/cars/mods/<packname>/<carfoldername>.ini
```

- `<packname>` identifies the mod pack or creator. Use existing pack names when the car belongs to a known collection (`acclub`, `acfl`, `fo`, `rss`). For standalone mods with no associated pack, the file can sit directly at `config/cars/mods/<carfoldername>.ini`.
- `<carfoldername>` is the exact folder name from `assettocorsa/content/cars/`.

**Examples from the repository:**

| Car | Path |
|---|---|
| Formula car (RSS) | `config/cars/mods/rss/rss_formula_rss_2.ini` |
| Community club car | `config/cars/mods/acclub/peugeot_504.ini` |
| Standalone mod | `config/cars/mods/caterham_academy.ini` |

## Key Sections Reviewers Check

When a maintainer reviews your pull request, they will focus on:

- **Correct mesh and material names** — every value passed to `NAME =` in an `EMISSIVE_*` section must match a mesh or material that actually exists in the car's KN5 model. Typos here cause the automated checker to flag the config.
- **Reasonable light positions** — `POSITION` coordinates are in metres relative to the car's root node. Headlight Z values should be clearly positive (forward), brake light Z values clearly negative (rear). Wildly out-of-range positions suggest a copy-paste error.
- **Emissive material names** — `EMISSIVE_LIGHT_X`, `EMISSIVE_BRAKE_X`, and similar sections drive the glow of specific lens meshes. Using a wrong material name means the lens never visually illuminates, even if the light cone itself works.
- **LOCATION tag correctness** — `LOCATION = FRONT` / `REAR` / `NONE` on emissive sections must match where the mesh physically sits on the car.
- **AFFECTS_TRACK flag** — set to `1` for exterior brake lights and headlights so the projected cone lands on track surfaces; set to `0` for interior instruments.
